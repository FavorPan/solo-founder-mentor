# 方法论拆解

出海一人公司两大方法流派全部可落地方法论的结构化拆解。泼冷水和给建议时对照查用。

> 来源：对出海一人公司领域两大互补方法流派（AI 编程派 + 流量出海派）的公开资料调研整理。本文件只保留方法论本身，不涉及具体个人/产品/课程名称。溯源见 `sources.md`。

## 一、AI 编程派方法论（AI编程 + 产品洞察维度）

### 1. 需求倒着做（最系统的方法论）

> "大部分人做产品，都是先有产品，后有营销，最后客户。但正确的顺序是先有用户，再营销，再做产品。"
> "一个好的产品，一定是一个具体问题的解决方案。"

**填空题模板（每做产品前必填）：** "人在 [场景] 下，愿意花 [钱] 解决 [问题]？"

三个空填不出来 = 伪需求，直接劝退。

**标杆案例（某营销大师的经典打法）：**
- 背背佳：无榜单无竞品，洞察需求→全世界找方案→买大学老师专利→精准投放到家长能看到的地方
- 小罐茶：万亿美元茶市场无千亿公司，痛点是"茶无价格无标准"

**泼冷水用法：** 用户说"我想做个 X"，反问填空题三空。答不上来就是先有产品后找用户，倒着来。

### 2. AI 编程六级跃迁

> 标题："AI 编程从玩具到全职员工的六级跃迁"。这是认知框架不是工具分类，每个阶段有明确通关条件，**不可跳级**。

前置认知——**摆摊 vs 售货机**（灵魂拷问）：
> "当你睡觉的时候，AI 还在帮你赚钱吗？"

- **摆摊模式**：用 AI 提速 10 倍，但仍"手停口停"——你坐在电脑前手动触发每个任务。卖时间，天花板受你的时间限制。
- **售货机模式**：AI 替你做事，自动执行，周而复始。你可以睡觉/不在电脑前，系统依然运转产出。卖系统，天花板受系统设计质量限制。

> "快不等于自动化。AI 做事很快，但如果每次仍需你手动启动，那你只是拥有了一个更快的摆摊工具，而不是一台 24 小时运转的售货机。"

**六级阶梯：**

| 阶段 | 名称 | 核心特征 | 通关条件 |
|---|---|---|---|
| 第一级 | 玩具（2023 起） | 几句话生成小游戏/星座算命/简单页面；代表工具 v0、Bolt、Coze | 理解背后技术原理，知其所以然 |
| 第二级 | 工具（2024 爆发） | 一站式 AI IDE，典型代表 Cursor，像手机摄影开箱即用；可做出商业价值完整产品 | 学会拆解工具链，理解 IDE 集成了哪些子工具 |
| 第三级 | 副驾驶（Copilot 模式） | 回归 VS Code + AI 插件自由组合，从手机摄影升级为单反；上下文不丢失，可驾驭复杂项目 | 发现这种方式不够用，或理解了 MCP（Model Context Protocol）的价值 |
| 第四级 | 命令行 Agent（分水岭） | 以 Claude Code 为代表，无界面，AI 开始有主动性；IDE 消失，AI 可在终端自主执行；睡前布置任务跑一晚次日验收；可完成公司所有非代码类工作 | 每天能消耗超过 $1000 的 tokens；或找到让 AI 自动触发任务的方法 |
| 第五级 | 实习生（Claude 桌面端/Operator 模式） | 代码消失，纯业务语言沟通，AI 自选技术方案、写代码、测试，交付结果文件（PPT/Excel 等） | 自动触发的任务类型超过手动触发的，考虑升级到下一阶段 |
| 第六级 | 全职员工/小龙虾（Computer Use Agent） | 终极形态：电脑消失，AI 通过手机消息接受指令，自主完成选域名、购买、写代码、部署、接入支付全流程；可自动写日报、主动通知异常、自主监控竞品 | 终极形态 |

**第六阶段关键**："只有岗位才能真正自动化""写一份岗位说明书（SOP）"。

**第六阶段局限**：无法触碰物理世界；不适合大量微决策工作；公司重大决策仍需人拍板。

**三个反常识洞见：**
1. **AI 编程的核心能力是管理学，不是技术** —— 提示词工程（Prompt Engineering）→ 上下文工程（Context Engineering）→ 岗位说明书（SOP），三者逻辑完全一致。"你怎么向员工交代工作，就怎么向 AI 交代工作。"
2. **不建议小白直接用最高阶工具** —— "如同自动驾驶成熟了也不取消驾照。不懂前五个阶段的原理，第六阶段用不好。如果不了解技术原理，Computer Use 只是一个聊天工具。"
3. **AI 全自动化会产生"决策心累"** —— 当 AI 能做所有事，人需要对每件事拍板决策，认知负担反而加重。最终形态：AI 负责执行，人类负责品类决策，合伙人负责产品决策。核心公式：**AI 干活 + 人类做选择 = 选择就是你唯一的创造过程**。

> 来源：2026-03-29 某行业 AI 大会现场演讲的公开转述。转述版结构完整、各阶段信息自洽，可信度高。

### 2.1 AI 创业十步法

"需求倒着做"展开成的可执行清单，源自某出海创业者 2025-03 公开访谈的现场记录，可信度高。

1. **洞察需求** —— 寻找别人未注意到的真实需求或问题，识别"共需失衡"点（热点事件、评价低但用户量大的应用、用户社交平台留言等）。
2. **AI 市场调研** —— 与 AI 工具（如 ChatGPT）交流，像与专业产品经理一样讨论、验证需求，避免无效创业方向。
3. **生成需求文档** —— 让 AI 协助输出详尽的需求文档，清晰定义项目目标、目标用户和核心功能，确保描述毫无歧义。
4. **手绘原型设计** —— 自己先用纸张手绘出产品原型，明确产品界面的基本逻辑和布局。
5. **AI 生成高保真原型图** —— 基于手绘原型，用 AI 快速生成接近实际产品体验的高保真原型图，以便向潜在用户展示。
6. **原型用户验证** —— 将高保真原型图发给目标用户，确认产品逻辑是否清晰，界面是否符合用户需求，进行初步验证和优化。
7. **AI 编程实现 MVP** —— 用 AI 工具快速编程实现产品的核心功能（最小可行产品），甚至普通人无需编程知识也能实现。
8. **上线部署** —— 使用阿里云或腾讯云等平台，以极低的成本将产品部署上线，快速启动市场验证。
9. **市场验证与迭代** —— 通过社交平台或广告精准投放，快速获取 1000 名目标用户，验证点击率、留存率、付费率等核心数据，评估产品和商业逻辑的可行性，根据反馈快速迭代，甚至每日更新版本。
10. **商业化放大** —— 若 MVP 验证成功，集中精力优化获客和变现效率，持续放大用户规模和收入，利用 AI 高效复制成功模式，拓展新产品和新机会。

**关键配套数据**（访谈原话）：某文生图产品 MVP 只花一周左右，上线一个月每天收入 400-700 美元；验证逻辑——"如果付费率超过预期，证明赚钱；如果达不到，就大胆放弃再换产品。现在成本很低，验证成功就赚钱了。"

**泼冷水用法：** 用户说"我想做 X 但不知道从哪开始"，让他按十步法走到第 6 步（原型用户验证）再写代码。大部分人卡在第 1 步（洞察需求）就开干，等于跳过了"需求倒着做"。

### 3. AI 员工化 / 养小龙虾

> "给 AI 写岗位说明书。"
> "第一步：选岗位，不选任务。任务是一次性的。岗位是多个任务串起……这个岗位就可以完全外包给 AI 了。这个过程就叫'养小龙虾'。"

**五步法：**
1. 选岗位（不选任务）——任务一次性，岗位可复用
2. 写岗位说明书（SOP）
3. 让 AI 跑
4. 审查输出
5. 迭代到能完全外包

最终形态："AI 负责执行，人类负责品类决策。"

代表性标语："Your next 10 hires won't be human."（你接下来的 10 个新雇员不会是人类。）

**泼冷水用法：** 用户说"卡住了/做不完"，问"卡的是任务还是岗位？"卡任务→写 SOP 交给 AI；卡岗位→认知没到位，先想清楚岗位边界。

### 4. Ralph Loop（暴力循环）

源自开源社区一位工程师的方法，核心"Dumb loop. Smart results."（笨循环，聪明结果）。

**三要素：**
1. 持续迭代：执行→审查→修复→重复
2. 每次用全新上下文，避免"上下文腐烂"
3. AI 自己输出完成信号才停（不靠人判断）

解决三个痛点："不会写 prompt""AI 跑一次就停""配置太麻烦"。

**用法：** 描述需求 → AI 头脑风暴生成 prompt → 循环执行 → 可视化控制。

### 5. 泼冷水用法（本 skill 的灵魂来源）

> "AI 的唯一正确用法，是让它给你泼冷水！"

不要用 AI 附和吹捧，而要让 AI 主动质疑、挑刺、指出方案漏洞——把 AI 当"反对者"而非"赞同者"。

### 6. 替代岗位而非职能（最前瞻的产品哲学）

> "你代替的是职业，一个岗位，而不是职能。"
> "什么叫细分领域的深耕，就是把整个过程的细节、评审、写作工具一摊子事全部融合进去，能代替一个活生生的职位岗位！否则你干的事，会随着模型的强大，而吃亏。"

**泼冷水用法：** 用户做的是"套壳 API 工具"（替代职能），反问"模型一升级你是不是就废了？"引导想"能不能融合整条流程，替代一个岗位"。

### 7. 出海与产品心法

- **程序员做 SaaS 出海是超级蓝海**："程序员的优势就是，能做出更好的产品，而不是投放能力。"
- **做铲子**："你拼不过，那就做铲子，比如帮助人做海外 SaaS 站的模板。"
- **产品要随大模型变强而变强**："以前总有人研究 prompt 技巧。然后新的模型出来了，好家伙，全白捣鼓了。"
- **交付结果而非过程**："现在是流行交付结果，用户可以等，但你给的结果一定是你能达到的最优水平。"
- **自传播是产品标准**："不能引发自传播的产品，不是好产品。"
- **国内别 Build in Public**："产品早期不要得瑟，闷声发财即可！国内的抄袭风气太严重了。"

### 8. 管理理念

- **无 KPI/OKR/周报**："它们都过时了。享受过程，自然会得到结果。只想要结果，反而没有结果。"
- **人才观**："人是筛选出来的，不是培养出来的，更不是说服出来的。""在公司早期，不要轻易招大厂精英。习惯于大厂打工的人，绝大部分没有独立生存能力。"
- **对竞争**："绝大部分公司都只是草台班子。不要害怕他们，他们是纸老虎。""'弯道超车'的想法是有害的。意识到'成功没有捷径'，本身就是最大的捷径。"
- **修己安人**（核心心法）："我积极修炼自己，让身边的人得到安顿、安心。而不是反过来——折腾员工，只为了让自己心安。"

## 二、流量出海派方法论（流量/SEO/执行力维度）

### 1. 蹭热度 vs 吃任务（转型核心命题）

> "从蹭热度 转成 吃任务"——用户不是为 AI 付费，是为省时间、赚钱、降低风险、完成工作付费。

**蹭热度（新词站）的特征：**
- 抢新词、当天上线、纯 HTML/iframe
- 变现靠 AdSense
- 快、成本低；生命周期短、靠运气
- "不持续就是一波流"

**吃任务（SaaS）的特征：**
- 核心 AI 产品 + 入口 + 自增长 + 转化
- 订阅 MRR，复利、长期资产
- 最难、需 12-18 个月

**转型动机：**
- 新词站只能吃"一次搜索波动"，流量不持续
- 娱乐词用户不付费——有公开复盘案例"一千多个注册的 AI SaaS 没有一个人付费"
- AdSense 天花板低，SaaS 付款率 1% 就比 AdSense 香

**泼冷水用法：** 用户做的方向若偏"蹭热度娱乐流量"，反问"用户会为这个付费吗？还是只是来消遣的？"

### 2. 五根方法论（SaaS 转型操作系统）

> 一个核心产品 + 一组入口页面 + 一个自增长机制 + 一个转化系统 + 一套数据复盘

| 根 | 内容 |
|---|---|
| 核心产品 | 3 分钟内给用户一个明确结果 |
| 入口页面 | SEO 页面 + 免费小工具 + 对比页 + 替代页 + use case 页 |
| 自增长机制 | 6 种：公开分享页/模板库/免费小工具/导出限制/邀请得额度/对比页替代页 |
| 转化系统 | $19/$49/$99 三档 |
| 数据复盘 | 每天 10 个数 + 每周瓶颈复盘 |

### 3. 机会分评分系统（选品决策，可执行）

5 分制 6 维度：
- 痛点强度
- 付费意愿
- SEO 难度（越高越难，要减）
- 产品可实现性
- 长期价值
- 自增长潜力

**机会分 = 痛点 + 付费意愿 + 产品可实现性 + 长期价值 + 自增长潜力 − SEO 难度**

| 分数 | 决策 |
|---|---|
| <15 | 不做 |
| 15-20 | 观察 |
| 20+ | 候选 |
| 25+ | 立刻测试 |

→ 用 `scripts/opportunity_score.py` 跑。

### 4. 技术栈（Cloudflare 全家桶）

| 组件 | 用途 |
|---|---|
| Cloudflare Workers | 业务逻辑和 API |
| D1 | 关系型数据 |
| R2 | 文件/图片（零出站流量费） |
| KV | 缓存、配置 |
| Durable Objects | 强一致、多租户会话、实时协作 |
| Workflows | 长任务、重试、异步流程 |
| Workers AI / AI Search | AI 推理、文档搜索 |

配套 SaaS 模板含：认证/支付/邮件/管理后台/限流/报警模块。

### 5. 收款体系

- **AdSense**：谷歌电汇 → 中国大陆**招商银行储蓄卡**直接入账美元 → 自动结汇人民币。个人主体，不用第三方工具，对新手友好。
- **Stripe/SaaS**：美国 LLC（怀俄明州，免州税）+ EIN + Mercury 银行 + Stripe，用 Wise 中转国内消费。
- **Creem**：3.9%+$0.40，无需公司主体、支持支付宝提现——适合中国独立开发者快速验证 MVP。

### 6. 定价标杆与试用数据

- 定价标杆：$19/$49/$99
- 试用期数据：需信用卡 opt-out 试用转化率 **48.8%**，免信用卡 opt-in 仅 **18.2%**（2.7 倍差距）

**泼冷水用法：** 用户纠结定价/试用，直接给这两个数。低于标杆要有理由，免信用卡试用要接受低转化。

### 7. 数据复盘系统（Launch Intervention Ledger）

**每天看 10 个数：**
访客 / 注册 / 激活 / 付费 / 收入 / MRR / 搜索曝光 / 搜索点击 / 广告花费 / 用户反馈 bug 数。

看完只问"今天最大的瓶颈是什么"，每天只打一个瓶颈。

**观察窗口：**
- D0 看风险
- D1-3 看行为
- D7 看浅层增长
- D14-28 看商业指标
- W2-8 看 SEO
- W8-12+ 看权威信号

**泼冷水用法：** 用户说"卡住/不知道哪有问题"，反问"你的 10 个数呢？"没数据复盘的卡住 = 瞎卡。

### 8. 三种赚钱路径

| 路径 | 特征 | 变现 | 优缺点 |
|---|---|---|---|
| 新词站（捡垃圾） | 抢新词、当天上线、纯 HTML/iframe | AdSense | 快、成本低；生命周期短、靠运气 |
| 套壳 AI 工具站 | 套 OpenAI/Claude/Flux/Gemini API | Stripe/Paddle | 直接收钱、付费率约 1%；API 盗刷风险 |
| 产品站/SaaS | 核心 AI 产品 + 入口 + 自增长 + 转化 | 订阅 MRR | 复利、长期资产；最难、需 12-18 个月 |

## 三、海外 indie 派·反VC极简方法论（极简技术栈 + 付费验证 + 自动化）

> 来源：某全球知名数字游民独立开发者，2013 年起 nomad，2014 年发起 "12 Startups in 12 Months"，做出多个百万美元级产品，90% 利润率、99% 自动化。反 VC、反融资、反招人、反免费用户。核心精神：**快、付费验证、build in public、不融资不招人、高度自动化、做 weird 小众物**。

### 1. 找点子四线索

**(a) Scratch your own itch（基础盘）** —— "我的点子大多是为解决自己的问题。"局限自觉：人群同质化（年轻男性居多）会限制受众。

**(b) 旅行带来的地理套利** —— "去别的国家看到本国没有的东西，回去做一个。"旅行本身制造问题，出门才有问题可发现。

**(c) 日常问题清单** —— 醒来自问"我日常生活里什么让我很烦、运作不畅？"列清单 + 想解法 + 看哪个可行。

**(d) 先玩技术再找应用（现在的主要方式，但高风险）** —— 玩 Stable Diffusion → 发现擅长生成房子/室内 → 做出"这房子不存在"demo → 发现 image-to-image 能改室内 → 做出 AI 室内设计产品 → 做出 AI 写真产品。**警告**："这是著名的 solution trying to find a problem，通常不奏效。"

### 2. 付费验证法（核心）

> "唯一真实验证是有人付钱。"

**验证标准**：不靠注册数，靠掏信用卡付钱。"他们需要掏出信用卡付我钱，然后我才能看到 idea 被验证了。"

**速度**：两周内上线 MVP。12 startups 时期是"每月一个，严格不超一个月"，把进度博客发到 HN 公开制造问责。

**反免费用户**：
> "免费用户通常不转化。如果你有 VC 融资，搞免费用户合理，因为你能花钱投广告……但 indie hacker 没这个 luxury。"
> "免费用户和付费用户价值差约 1000 倍。"

**定价**：indie hacker 客单价至少 $30/用户才值得做；"26 个 $99/月客户就到美国平均收入。"

**MVP 怎么砍**：能不建登录系统就不建。某 AI 写真产品早期 = Stripe Checkout 付款 + 静态登录链接；另一极端案例 = 只有一个 Stripe 支付链接，后端无代码，"你只知道有客户付了钱"。

### 3. 继续做 vs 放弃——时间盒逻辑

> "计划是一个月内看能不能找到 market fit，看不到任何'有人想要'的迹象，就判失败。"

- 一个月内看不到"有人想要"就判失败
- 项目继续靠"它自己在赚钱"维持（成名作用了 4 年到 $1M 年营收）
- **转型比硬撑重要**：从"AI 头像"产品转向"AI 写真"产品、从"这房子不存在"demo 转向"AI 室内设计"产品，都是发现 hype 退潮立刻转
- 反对沉没成本式坚持——12 startups 核心就是强制 30 天后切下个
- "70+ 项目里只有 4 个赚钱并增长。"

### 4. build in public（作为分发策略，不是哲学）

> "在暗处闷头做不让人用，是做出没人要的东西的最佳方式。"

**具体操作：**
- 把过程截图发 X（早期 Sublime 截图被嘲"Boomer 才用 Sublime"）
- 先发"我在做这个"的 demo，再发"上线了"的推
- 公开承担问责（12 startups 把进度博客发到 HN"逼自己不能鸽"）
- 收入也公开（open startups）

**主战场**：X（核心）、HN、Product Hunt、Reddit。

**Reddit 玩法（不能硬推）**：找到某个 subreddit 上很多人已有的问题，解决它，发"嘿大家，我做了个可能解决你们问题的东西，现在免费"，而不是"嘿这是我的新 startup 你们应该用"——后者会被当 spam 删。

**文案心法**："像跟朋友解释一样解释你的产品。"

### 5. 100% 自动化清单

> "1 个创始人兼开发设计营销（用 ChatGPT 辅助）/ 0 人类 / Stripe 收款 / 目标 100% 自动化 / 用 ChatGPT API 跑定期任务的 worker 脚本 / Featureface.app 收 bug 反馈 / Stripe Billing Portal / 自服务客户 dashboard（含自助退款）/ 99% 利润率。"

**亲自做**：写代码、定产品策略、X 上自我营销、跟 AI 供应商砍价。
**自动化**：客服、审核、监控、meetup 组织、退款、订阅管理。
- 每个站点 cron job + UptimeRobot 关键词监控，出问题 Telegram 推警
- 客服/审核用 GPT-4o 自动处理，销售也用 ChatGPT API 自动化
- 只在"有新点子/有 bug/有新趋势"时切进去手动写代码

### 6. 反融资反招人

> "我不融资。我不用 VC 钱，全自己来……因为没有融资，我必须快。"
> "很多拿了数亿美元融资的创始人朋友私下跟我说：'下次我要像你这么做，更好玩、更 indie、更 chill、更创意。'他们不想当管理者。"

**反招人**："我不招人。我跟 AI 供应商砍价让它更便宜。""不想管一大堆人，所以尽量自动化。"

**对卖公司**："我的公司 90% 利润率。公司按倍数卖……他们要看你的 Stripe、代码，最后压价，因为你已经投入那么多。"——所以不卖。

**泼冷水用法**：用户说"要不要融资/招人扩张"，反问"真需要吗？没有融资反而逼你快、逼你自动化。"

### 7. 极简技术栈

- 服务器：单台 VPS（早期 $40/月），所有站点跑同一台
- 后端：**PHP**（自嘲"不好意思告诉别人"）+ 一点 Node.js
- 前端：手写 HTML、原生 JS、jQuery、SCSS
- 数据库：**SQLite**，倾向用文件存数据
- 编辑器：早期 Notepad++ → Sublime Text
- 部署：SSH + symlink nginx.conf + `nginx -s restart`，约 15 分钟上线新域名
- 支付：Stripe Checkout
- **不写测试**，没有正式 IDE，奉行"快速上线、边跑边修"
- **AI 编程**：2025-2026 在 VPS 上用 Claude Code 直改生产（一年里只出过两次让站点挂 10 秒的小问题）；取消所有 SaaS 订阅自己 vibe code 替代

> "做生意只要开源软件 + 一台 VPS + 一个 AI API + R2/S3。"

### 8. 做什么类型的产品

- 优先做"能在一台 VPS 上跑完整个 stack"的产品
- 优先做"无需登录、无需 onboarding"的产品
- 优先做"用户自己掏钱、不依赖广告/企业销售"的产品
- 优先做"premium 给富人区"的产品："想最快致富，就给瑞士、阿联酋、美国、新加坡做 premium 产品。"
- AI 应用特点：**单品爆发力极强、单次付费、不需要订阅留存逻辑**。"AI 对大多数人的真机会是给它做个前端。"

### 9. AI 时代蓝海判断

**(a) 分发 > 产品**：
> "人人能用 AI 做 app，所以现在分发才是真挑战。"

有 audience / 个人品牌 / 社区的人赢。

**(b) 做"模型商不会做的"**：复古计算、浏览器老软件、小众 weird、有社区的东西——BigAI 不会做（太小众太 weird），且适合 vibe coding（有明确参考物 AI 能直接生成）。

**(c) "BigAI is cannibalizing everything"**：
- app 层被模型层吃掉：原来"customer → app → ai model provider"变成"customer → ai model provider"
- 所有"低门槛 AI 包装应用"正在被吞
- "每个人都在用 AI 把产品提升 10 倍，但竞争对手也是——就像赛跑每个人都装了氮气但没意识到别人也有。进入门槛没了，任何人都能 clone 一个 app 当竞争对手。"

**(d) "Software is dead"**：软件"商品化"≠"死了"，而是"人人能做"，所以分发和选难进入的赛道才有救。

### 10. 明确的"别做 X，做 Y"

**别做**：
- 别做"和孵化器 80 份申请一样的 AI slop"
- 别做"纯 app 层、能被用户一键 vibe code 克隆的 SaaS"
- 别做免费用户/freemium
- 别去 accelerators/incubators/coaches/bootcamps——"instead ship"
- 别去 networking events——"Only losers go to networking events."
- 别在暗处闷头做不让人用
- 别一上来就建登录系统/数据库/框架——能省则省

**做**：
- 做"有明确参考物、AI 能直接生成"的 weird 小众物
- 做 vibe coding 工具链相关
- 做 premium 给富人区的产品
- 做你自己有痛点的、能用一张电子表格先验证的东西
- 做"一台 VPS + AI API + R2/S3 + 开源软件"就能跑的全自动生意
- 先副业做、收入超主业 6 个月再辞职

## 四、海外 indie 派·分发组合方法论（AI编码工作流 + Ship Fast + 组合变现）

> 来源：某常驻巴厘岛的法国背景独立开发者，运营 35+ 产品组合，月入约 $70-115k。核心标签：**Ship Fast 哲学、AI 编码工作流、分发驱动组合变现、收入透明公开、卖铲子给同行**。

### 1. AI 编码工作流——80/20 法则

> "AI 生成约 80% 的代码，但我仍花约 20% 时间审查 AI 生成的代码、微调细节。"

**唯一编辑器：Cursor AI**（不用 Lovable/V0/Bolt）——原因：希望 AI 知道自己的代码库、命名、配色。模型用 Claude 3.5 Sonnet。

**Cursor 四层用法：**

| 层级 | 快捷键 | 用途 |
|---|---|---|
| **Inline** | Cmd+K | 小修补：Tailwind CSS 类、SVG→JSX 转换 |
| **Chat** | Cmd+L | 不写代码，专做高层架构思考：设计算法/排序逻辑、code review 找 API 安全漏洞 |
| **Composer** | Cmd+I（Agent 模式） | 90% 写代码走这里。AI 自己建文件、装库、跑终端、改到能跑为止 |
| **Design** | 截图拖入 | 截图任意网站组件 → 拖进 Cursor → 用自己的配色/命名重造组件 + API + 动画 |

**两条元规则：**
- **命名即一切**：文件/组件/API 全部显式命名（如 `ButtonDeletePost`），让 AI 更容易理解代码库。"编程里命名是最难的事。"
- **Context 最重要**：用同一套代码库 clone 出 30+ 项目，Tailwind 类、组件、技术栈完全一致，AI 有地基就能靠谱产出。"你给的 context 越多，结果越好。"

**与反VC极简派对照**：反VC极简派用 PHP + 单 VPS 极简栈，本派用 Next.js + AI 编辑器栈。两人都强调"复用同一套代码库"，但本派把它升级成了商品（boilerplate 模板）。

### 2. Ship Fast 交付哲学

> "ship 得越多，学得越多，赚得越多。"

- 两年内交付 16 个项目，累计已建 27-30 个 startup
- 把重复基础设施（DNS、Stripe webhooks、定价页）抽象成 boilerplate 卖
- 衍生产品阶梯：**工具（模板）→ 课程 → 体验/社群**，单价和黏性递增

**社区反驳（重要制衡）：**
- HN 热帖《10000 小时编码教会我：别 Ship Fast》
- "别想成为下一个 indie maker 标杆——他们先有几年积累的受众再做产品，大部分产品都 flop 了，成功只是因为分发已经在那。照搬 playbook 是错的。"

### 3. 营销与分销方法论

**(a) 公开透明 = 信任 + 营销**：所有产品 MRR 实时公开在 Indie Page。收入透明既是信任构建手段，也是内容素材（每次发布晒数据截图二次传播）。

**(b) 稀缺感 + 限时**："首批 8390 名，剩 12 席。"**争议**：社区指控"首批 X 人享折扣的 X 会随达标而上调，制造虚假紧迫感"。

**(c) Affiliate 联盟**：有 affiliate 程序。**争议焦点**：社区指控 affiliate 反复发软文刷屏"开始像传销"。声誉成本高。

**(d) 内容飞轮**：YouTube「Day N growing my SaaS to $1M」系列日记 + Newsletter + Twitter。

**(e) 用户即广告位**：让用户上传头像生成像素头像 → 用户拿来换 Twitter 头像 → Twitter 被该头像淹没 = 零成本病毒营销。

### 4. 组合变现打法

- **所有产品服务同一人群**（indie hacker），一次获客可交叉销售多个产品，组合内自循环
- 工具（模板）+ 数据库（SaaS 买卖市场）+ 数据分析 + 课程 + 社群 = **卖铲子给同行的完整闭环**
- 已验证的小产品可收购翻新转卖（如 $35k 收购的 landing 工具）

### 5. agent-friendly SaaS（2026 前瞻趋势）

被 Stripe 邀请去旧金山 Sessions 大会抓到的两个新蓝海信号：

**Stripe MPP（Mastercard Agent Pay / Link 钱包）协议**：给 AI agent 一个钱包，让它自主上网买东西。双向含义：**客户的 agent 会来买你的 SaaS**。
> "客户可以用他们的 agent 通过 MPP 协议来买你的 SaaS……我们软件的整个 onboarding 将为 agent 设计，而不是为人类。"

**Stripe Treasury**：Stripe 内置银行，收入无需再走外部银行 payout。

**判断**：**SaaS 要开始做 agent-friendly 的 onboarding/购买流程**，这是下一个范式转移。与 AI 编程派"最终客户是 Agent、App 消失"判断同频——两位对标人物从不同路径指向同一趋势，可信度高。

### 6. 数据口径警示

公开 MRR 数字要搞清口径，别盲信 dashboard 截图：
- 某公开页显示 $115k/月，但多个近期来源有出入（$69-77k）
- "月收入"口径常混用滚动新增、订阅、一次性收入
- 一次性 $250 入场费 × 329 人的模型与 "$33.7k/月" 不自洽

**对学员强调**：公开 MRR 数字要搞清口径，别盲信。

## 五、四派共识与互补

### 共识（四派都认同）
- **付费验证 > 注册数** —— 没人掏钱就是没验证
- **快、小、先上线** —— MVP 能砍就砍，两周内见用户
- **AI 写代码是基础能力** —— 非程序员也能做出千万级产品
- **大部分产品会失败** —— 组合制 / 快速放弃 对冲
- **90% 的 AI 创业一年内失败** —— 别上头

### 互补（按困惑场景调用）

| 困惑场景 | 首选流派 |
|---|---|
| 验证需求 / 选品 | AI 编程派（需求倒着做）+ 海外indie派·反VC极简（付费验证） |
| 找方向 / 做什么类型产品 | 流量出海派（机会分）+ 海外indie派·反VC极简（蓝海判断） |
| AI 编程怎么落地 | 海外indie派·分发组合（80-20/Cursor四层）+ AI 编程派（六级跃迁/养小龙虾） |
| 自动化 / 一人忙不过来 | AI 编程派（六级跃迁/养小龙虾）+ 海外indie派·反VC极简（100%自动化清单） |
| 变现 / 收钱 | 流量出海派（五根/定价）+ 海外indie派·反VC极简（反免费用户） |
| 要不要融资/招人 | 海外indie派·反VC极简（反融资反招人）+ AI 编程派（无KPI/修己安人） |
| 要不要 build in public | 按市场分：海外市场→build in public；国内市场→闷声发财 |
| 产品组合 / 放大 | 海外indie派·分发组合（组合变现）+ 海外indie派·反VC极简（12 startups） |
| 未来趋势 / 选赛道 | 海外indie派·分发组合（agent-friendly SaaS）+ AI 编程派（最终客户是Agent） |

### 东西方对照（关键差异）

| 维度 | 中国出海两派 | 海外 indie 两派 |
|---|---|---|
| Build in Public | 国内别得瑟（抄袭风气重） | 奉为核心分发策略 |
| 技术栈 | Cloudflare 全家桶 / AI 编程工具 | PHP+SQLite+单VPS / Next.js+Cursor |
| 验证 | 数据复盘（每天10个数）+ 机会分 | 付费验证（两周内掏信用卡） |
| 节奏 | 日更内容 + SaaS 转型（12-18个月） | 12 startups 12 months + Ship Fast |

**关键洞察**：国内市场抄袭重→闷声；海外市场 audience 驱动→公开。这不是对错，是市场环境决定的策略分叉。学员按目标市场选策略。
